# lumenandpixel.com

Source for **www.lumenandpixel.com** — a bilingual (EN/PT) static site served by
GitHub Pages from `main`. The custom domain is set in `CNAME`.

The published site is not compiled: whatever is on `main` is what is live, and
every page can be edited directly in the GitHub web UI. That editability is the
property worth protecting — not the absence of tooling. One generated file does
exist (`base.css`, see [Dev tooling](#dev-tooling-_tools)), and it is
regenerated by hand.

## Layout

```
index.html, about.html, services.html, quiz.html,        English pages
resources.html, legal.html, 404.html, thank-you.html
pt/…                                                     Portuguese mirrors
field-notes/, pt/field-notes/                            Field Notes hubs + article templates
site.css, site.js                                        Shared styles and behaviour
fonts.css, fonts/                                        Self-hosted webfonts
images/                                                  Logos, icons, gradients
CHANGELOG.md                                             What changed, and why
```

## Shared files — read this before editing a page

Stylesheet order matters and is deliberate:

```html
<link rel="stylesheet" href="/fonts.css" />
<link rel="stylesheet" href="/base.css" />   <!-- shared design system -->
<style> … page-specific … </style>            <!-- can override base -->
<link rel="stylesheet" href="/site.css" />    <!-- always has the last word -->
<noscript><style>.reveal{opacity:1;transform:none;}</style></noscript>
<script>window.__lpRevealFailsafe=setTimeout(…,4000);</script>
<script src="/site.js" defer></script>
```

- **`base.css`** is the design system: tokens, reset, nav, mobile menu, footer,
  accessibility primitives. **Edit here, not in a page.** It used to be pasted
  into 20 files, which is how one page ended up fixed while the others stayed
  broken. Generated by `_tools/extract-base-css.mjs`.
- **`site.js`** owns scroll-reveal and the mobile menu (open/close, Escape,
  focus trap, scroll lock). Do not paste that logic back into a page.
- **`site.css`** holds reduced-motion support, mobile-menu focus safety, `svh`
  units and the form honeypot style. It loads last and wins ties.
- **`fonts.css`** serves Space Mono and Nunito from `/fonts/`.
- The inline `<script>` failsafe reveals content if `site.js` ever fails to
  load. `site.js` cancels it on startup.

A page can still override anything in `base.css` from its own `<style>` — that
is what the ordering buys.

Page-specific JavaScript (contact form, quiz, Field Notes filter, newsletter)
stays inline on its own page.

## Dev tooling (`_tools/`)

There is one build step, and this is it. It is run **by hand**, its output is
committed, and nothing verifies that `base.css` matches the pages it was
generated from — so a page edited in the web UI can drift from it silently.

```bash
cd _tools && npm install
node extract-base-css.mjs --check    # report duplication, change nothing
node extract-base-css.mjs            # regenerate base.css and strip the pages
```

`postcss` is a dev dependency only; it never reaches the browser. `_tools/` is
kept out of the published site by a GitHub Pages behaviour, not by anything in
this repo — see [Host dependencies](#host-dependencies).

## No third-party code in the browser

A page load makes **zero off-origin requests**. No analytics, no tracking, no
embedded marketing scripts, no CDN fonts — so the site sets no cookies and needs
no consent banner. Keep it that way: anything new that runs in the visitor's
browser changes the site's legal position and means updating `legal.html` and
`pt/legal.html`.

This covers **page load**. Submitting a form is different, and the distinction
matters:

| Endpoint | Called from | Used by |
|---|---|---|
| `…/webhook/inbound-lead` | `about.html:513`, `pt/about.html:482` | contact form |
| `…/webhook/newsletter-signup` | `index.html:423`, `pt/index.html:369` | newsletter |

Both are `fetch()` calls in **inline browser JavaScript**, fired when the
visitor submits. There is no server side to this site, so there is nowhere else
they could run.

**Both webhook URLs are therefore public** — in the served HTML, in this repo,
and in any visitor's network tab. Anyone can POST arbitrary payloads to either.
The only protections are in the page (honeypot, minimum fill time, format
validation), and a page's protections do not apply to a request that does not
come from the page.

That may be an acceptable posture for a two-form marketing site. It is not
currently a decision — see the webhook posture issue. Do not read the
zero-off-origin-requests property above as implying these endpoints are
protected. It says nothing about them.

Both live in n8n Cloud. See `CHANGELOG.md` v1.45 for the newsletter payload and
the double opt-in / unsubscribe behaviour the workflow is expected to provide.

## Host dependencies

Some behaviour comes from **GitHub Pages**, not from this repo. Anyone moving
the site elsewhere has to reimplement it or lose it:

| Behaviour | Provided by | If the host changes |
|---|---|---|
| `_tools/` and `_n8n/` are not published | Jekyll skips `_`-prefixed paths | Both directories become **publicly readable**. `_n8n/` contains workflow definitions. |
| `pt/field-notes.html` redirects to `pt/field-notes/` | Nothing — it is a `<meta http-equiv="refresh">` stub, because Pages cannot issue a 301 | Replace with a real redirect and delete the stub |
| Custom domain and HTTPS | `CNAME` plus the Pages configuration | Reconfigure at the new host |

The first row is the one to be careful about: there is no `.gitignore`-style
guarantee here. `_`-prefixed directories are private **only** because Jekyll is
running, and Jekyll is running only because Pages turns it on by default.

## Working on both languages

EN and PT pages are separate files that must be changed together. The language
switcher links each page to its counterpart; the logo always points at the home
page **of the current language**. The quiz passes its result to the contact form
as `?service=SD|SC|SA|TD` — both languages use the same English `<option>`
values, only the labels are translated.

## Checking your work

```bash
python3 -m http.server 8000     # then browse http://localhost:8000
```

Worth checking after any change: the page at 375px wide with the mobile menu
open, the page with JavaScript disabled, and — if you touched a form — that a
malformed email is rejected.
